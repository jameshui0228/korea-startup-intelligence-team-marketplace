# 요구사항 구현 대조 · 2026-09-18

사용자가 추가로 제시한 P0/P1/P2 및 9개 성능지표 **76개 항목**은 [ACCEPTANCE_76.md](ACCEPTANCE_76.md)에서 번호별 코드 경로와 운영/실측 대기를 별도로 대조한다. 이 문서는 그 이전의 Master/Trend 프롬프트 61개 절 대조를 유지한다.

첨부 Master 35개 절과 Trend 26개 절, 총 61개 절을 대조했다. **61개 항목에 대응 경로가 있다는 뜻이지 61개 기능이 완성됐다는 뜻이 아니다.**

`구현`은 실행 코드/테스트가 존재, `부분 구현`은 일부 코드와 에이전트 조사 필요, `조사 절차`는 원문을 읽고 판단할 지침을 뜻한다. v0.7.0 핵심 흐름은 사용자별 인증·예약 가동을 요구하지 않는다.
분류 지도·수집 건수·원문 검토·고객 검증·사업 성과를 서로 구분한다.

## 개인 운영·추가 연결

v0.4.0은 `operator` 운영체제를 추가했고 v0.5.0은 월간 배분·작업 결과·승인 상태·신호 그래프·변화 이력까지 연결했다. 확인된 창업자 자원과 후보별 요구량을 분리하고,
WIP/시간/예산 초과를 성공확률 점수 없이 보여 준다. 설정된 정책과 `--apply`가 있을 때만 로컬 후보를 보류·폐기·재개하며,
모든 변경은 revision과 event로 남긴다. 인터뷰→MVP→가격→GTM은 기존 불변 validation plan/result에 연결되고,
출시 KPI는 사용자 소유/허용 거래·집계 근거만 받는다. 주간 CEO 브리핑은 계획·실제 시간/지출·KPI·다음 결정을 함께 보여 준다.
고객 연락·광고·결제·게시·출시는 자동 실행 대상이 아니다.

텔레그램 고정 연결 확인 전송과 아이디어 전송은 따로 집계한다. 정확한 사용자별 현재 상태는 `telegram status`, `radar status`, 앱 자동화 설정을 우선한다. 공유 플러그인에는 토큰·수신 ID·사업 상태를 포함하지 않는다.

네이버는 사용자가 보류했다. YouTube 검색/집계는 구축 사용자 상태에서 live 확인했으며 새 사용자별 키가 필요하다. 기업마당은 실제 키 연결이 남아 있다. K-Startup·KOSIS/ECOS·Instagram 등은 범위/승인/어댑터 작업이 추가로 필요하다. [연결 순서와 한계](skills/korea-startup-intelligence/references/connectors.md)를 확인한다.
이 연결은 선택적 확장이다. 기본 조사·분석·아이디어·사업계획·발표/심사 작업은 현재 Codex와 공개 웹/사용자 자료로 수행하며 추가 API 키를 요구하지 않는다.

사용자의 최근 우선순위에 따라 외부 서버·LLM API·Telegram 추가 개발은 보류하고 플러그인 지능과 검증 기능을 강화했다.
0.5.0은 기존 설정값·활성 소스를 덮어쓰지 않고 누락된 비밀정보 없는 제품 기본값만 채운다. 기존 사용자 작업공간의 dossier 2건은 백업 뒤 명시적으로 편입했으며, 창업자 시간·예산·적합성을 임의로 채우지 않는다.

선정·수상·매출·모든 데이터 접근·완벽한 예측은 구현 목표의 성과 방향일 수 있지만 보장 기능으로 표시하지 않는다.
