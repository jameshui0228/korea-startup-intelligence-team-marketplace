# 실험 결과 0건에서 시작하는 사전검증 부트스트랩

## 목적

실험 결과가 없다는 이유로 아이디어 관리가 멈추지 않게 한다. 공개 원문, 공식 자료, 실제 대안,
창업자 제약과 명시적 가정으로 **조사·비교·실험 준비**까지 진행한다. 이 모드는 고객 검증을 대체하지 않는다.
공개 댓글, 검색 관심, 합성 페르소나, 시뮬레이션, 업계 평균을 인터뷰·거래·전환 결과로 바꾸지 않는다.

## 기본 흐름

1. `blue-ocean bootstrap --id ID`로 현재 근거와 validation 결과 유무를 읽는다.
2. claim ceiling에서 두 종류의 미확인을 분리한다.
   - desk research로 줄일 수 있음: 공급 공백, 시기, 한국 조건, 반대 근거.
   - 실제 고객/행동 자료가 필요함: 문제, 현재 지출, 접근성, 전환 이유.
3. learning lane을 따라 공개자료 근거표, 대안·가격 감사, 연락 전 채널 지도, 단위경제 가정 범위,
   첫 검증의 사전 기준을 만든다.
4. 사용자가 로컬 작업 생성을 원하면 `blue-ocean bootstrap --id ID --apply`를 사용한다.
   후보 단계, 외부 행동, 실험 결과는 바뀌지 않는다.
5. 실제 자료를 얻기 **전에** `validation plan` 또는 `validation qualitative-plan`으로 표본·측정·통과·중단 기준을 고정한다.

ID를 생략하면 전체 포트폴리오를 사업 성공 가능성이 아니라 **다음 학습의 의사결정 영향과 미확인 수**로 정렬한다.
같은 부트스트랩을 다시 적용해도 열린 작업을 덮어쓰거나 중복 생성하지 않는다.

## 데이터가 없어도 가능한 일

- 실제 공개 원문의 문제 표현·업무 흐름·반례를 주장별로 정리한다.
- 직접 경쟁, 간접 경쟁, 수작업, 현상유지 대안의 가격 단위와 전환 마찰을 비교한다.
- 창업자가 이미 접근 가능한 역할·장소·소개 경로를 확인하되 연락은 실행하지 않는다.
- 가격·직접원가·서비스 시간·반복 구매·CAC를 null로 둔 계산식과 민감도 질문을 만든다.
- 인터뷰, 수동 MVP, 가격 시험 중 무엇이 가장 큰 미확인을 가장 싸게 줄이는지 결정한다.
- 실험의 모집·원자료·분모·통과·중단·안전 기준 초안을 만든다.

## 데이터가 없으면 할 수 없는 일

- 문제 보유 고객 비율, 지불의향률, 전환율, 유지율, CAC, 반복 구매를 숫자로 확정.
- criterion_met 결과 생성, building/launched/scaling 이동, 시장 규모나 성공확률 확정.
- 가상 고객 인터뷰, 합성 구매, 임의 매출, 임의 보수/기준/낙관 숫자를 근거로 저장.

`assumption_envelope`의 값은 사용자가 확인하기 전 모두 null이다. 계산식을 제공하는 것과 시장을 측정한 것은 다르다.
외부 연락·광고·결제·게시·개발은 별도 요청과 승인 범위가 필요하다.
