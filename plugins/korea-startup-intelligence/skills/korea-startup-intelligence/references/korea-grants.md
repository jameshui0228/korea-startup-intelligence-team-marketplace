# 한국 지원사업·공모전·사업계획

## 공고 원문 우선

공고는 K-Startup, 기업마당, 중기부/창진원, 중진공, SBA, 지역 창조경제혁신센터, 지자체/대학,
NIPA, KOCCA, 관광·스포츠·농식품·환경 분야 담당기관 등 **해당 사업의 공식 원문**에서 확인한다.
기관 목록이 완전한 공고 수집을 의미하지 않는다. API 검색은 후보 수집이며 미구현 연결은 공식 브라우징/허용된 파일 가져오기로 보완한다.
공고 본문과 첨부의 연도·버전·정정·접수 기간·시각·지역·업력·연령·사업자 기준일·제외 업종·중복 지원·자부담을 대조한다.
보도 기사만으로 마감·지원금·자격을 확정하지 않는다. 날짜는 KST와 시각을 명시하고 마감 직전에는 다시 확인한다.

## 매칭

조건별 실행 점검에는 [공고 매칭](grant-matching.md)을 읽고 `grants save` / `grants match`를 사용한다.
일부만 읽었다면 conditions_complete=false, 시각을 모르면 null이다. 규칙·예외의 구조를 코드가 자동 해석한다고 주장하지 않는다.

창업자/사업정보가 없으면 자격을 UNKNOWN으로 둔다. 주민등록번호 등 불필요한 개인정보를 요구하지 않는다.
필수 조건별 표: 공고 조건 / 근거 위치 / 사용자 정보 / 충족·불충족·미확인 / 확인할 자료.
하나의 필수 조건이 불충족이면 가중 점수로 상쇄하지 않는다. 지원가능성과 선정가능성을 구분한다.
TIPS·패키지·청창사 등을 모든 사업에 적합하다고 일반화하지 않는다. 특정 연도 평가표를 사용한다.

## 심사 기준 연결

실제 초안·예산·발표·예상 질문까지 작성할 때 [지원사업 작업대](application-workbench.md)를 읽고 application prepare/save/check를 사용한다.
추가 API 키 없이 동작하며, 명령이 만든 질문 틀을 최종 사업계획으로 전달하지 말고 Codex가 실제 문장을 작성한다.

문제 → 원자료/고객 증거 → 기존 해결책/한계 → 차별화 → Why Now → 고객/시장 → BM → 경쟁 →
진입 채널 → 검증 → 팀 → 실행 일정·예산의 연결을 확인한다.
평가항목·배점·문항·글자수·페이지·서식은 공고에서 추출한 값만 쓴다. 시장성, 혁신성, 실행력,
사회적 파급, 지역·사업 정책 목적은 사업별로 다르다. “AI를 붙였다”는 혁신 근거가 아니다.

계획서 검토는 필수 문항/첨부 누락, 기간·단위·숫자 합계·자금 출처·KPI 간 모순,
근거 없는 확정 표현, 가설을 실적처럼 서술한 문장, 경쟁·권리·규제 누락, 실행 불가능 일정을 찾는다.
application check는 기록된 구조·출처·공고 현재성·자격과 예산 합계를 점검한다. 의미적 진실성/서식 렌더링을 자동 증명하지 않는다.
`plan-lint` 같은 외부 도구는 이 플러그인에 설치되지 않았다. 참고 색인과 동작 기능을 구분한다.
HWP/HWPX/DOCX/PDF 산출은 실제 사용 가능한 문서 도구로 처리하고 제출 전 렌더링/원문 대조를 수행한다.
본 v0.1 CLI가 HWP/HWPX를 만들거나 자동 제출하는 기능을 제공한다고 말하지 않는다.

## 최종 한계

선정 확률이나 수상을 보장/계산하지 않는다. 발표자료만 좋게 만드는 것보다 실사용자·거래·반복 수요 증거를 우선한다.
지원사업을 위해 사실을 부풀리거나 자격을 우회하거나 가짜 고객/협약/매출/추천서를 만들지 않는다.
신청서 제출, 기관 문의 발송, 비용 지출은 사용자의 명시적 요청이 있을 때만 진행한다.
